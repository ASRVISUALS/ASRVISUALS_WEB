# Deployment Checklist - ASRVisuals to Vercel

Complete this checklist before deploying to production.

## Pre-Deployment Setup (Local)

- [ ] Clone/pull latest code from repository
- [ ] Install dependencies:
  ```bash
  npm install --prefix backend
  npm install --prefix frontend
  ```
- [ ] Create `.env` files with all required variables:
  - `backend/.env` (MongoDB, Firebase, Cloudinary, JWT)
  - `frontend/.env.production` (API URL, Google Form ID)
- [ ] Test locally:
  ```bash
  cd backend && npm start
  # In another terminal:
  cd frontend && npm start
  ```
- [ ] Test admin dashboard: `http://localhost:3000/admin`
- [ ] Test contact form submission
- [ ] Test blog and portfolio pages
- [ ] Verify scroll-to-top on page navigation works
- [ ] Clear all console errors and warnings

## GitHub Setup

- [ ] Push all code to GitHub main/production branch
- [ ] All changes are committed and pushed
- [ ] No uncommitted changes in working directory

## Vercel Project Configuration

### Initial Setup (First Time Only)
- [ ] Create new Vercel project from GitHub repository
- [ ] Vercel auto-detects monorepo structure
- [ ] Connect GitHub account to Vercel
- [ ] Authorize Vercel to access repository

### Project Settings
- [ ] Root Directory: `/` (root of monorepo)
- [ ] Framework: `Other` (monorepo with custom builds)
- [ ] Build Command: `cd frontend && npm run build`
- [ ] Output Directory: `frontend/build`
- [ ] Install Command: `npm install --prefix backend && npm install --prefix frontend`

## Environment Variables (Vercel Dashboard)

### Frontend Variables
- [ ] `REACT_APP_API_URL` = Your backend domain
- [ ] `REACT_APP_GOOGLE_FORM_ACTION` = Full Google Form POST URL

### Backend Variables (in same Vercel project)
- [ ] `MONGODB_URI` = MongoDB connection string
- [ ] `JWT_SECRET` = Secure random string (change from development)
- [ ] `CLOUDINARY_CLOUD_NAME` = Your Cloudinary account name
- [ ] `CLOUDINARY_API_KEY` = Cloudinary API key
- [ ] `CLOUDINARY_API_SECRET` = Cloudinary API secret
- [ ] `NODE_ENV` = `production`
- [ ] `CORS_ORIGIN` = Your frontend domain

### Verification
- [ ] All env variables are set (no missing ones)
- [ ] Secrets are not hardcoded in source files
- [ ] `.env` files are in `.gitignore`
- [ ] Sensitive data is only in Vercel dashboard

## Domain & DNS Setup

- [ ] Custom domain purchased/registered
- [ ] Domain added to Vercel project (if using custom domain)
- [ ] DNS records updated (instructions from Vercel)
- [ ] SSL certificate auto-generated by Vercel
- [ ] Domain resolves to Vercel IP with HTTPS

### Optional: API Subdomain
- [ ] API on separate subdomain (e.g., `api.asrvisuals.live`)
- [ ] CORS_ORIGIN updated to match frontend domain

## Deployment Day

### 1) Pre-Deploy Testing
- [ ] Local frontend build compiles: `cd frontend && npm run build`
- [ ] Build output is in `frontend/build/` with no errors
- [ ] No TypeScript/ESLint errors
- [ ] No missing dependencies in package.json files

### 2) Database Backup
- [ ] MongoDB backup created (if using production DB)
- [ ] Backup stored securely
- [ ] Contact collection exported (if needed)

### 3) Final Code Push
```bash
git add .
git commit -m "Deploy: Add admin web update, video manager, scroll fix"
git push origin main
```

- [ ] Pushed to correct branch
- [ ] GitHub shows all changes committed
- [ ] No files in "Changes not staged"

### 4) Vercel Deployment Trigger
- [ ] Go to Vercel project settings
- [ ] Or: Vercel auto-deploys on git push
- [ ] Watch deployment progress in Vercel dashboard
- [ ] Deployment completes without errors
- [ ] Build time: ~2-4 minutes
- [ ] All previews/production domains show checkmark

## Post-Deployment Verification

### Immediate Checks (Once deployed)
- [ ] Frontend homepage loads: `https://your-domain.com/`
- [ ] No 404 or 500 errors
- [ ] CSS and images load correctly
- [ ] Favicon appears
- [ ] Page title is correct

### Navigation & Pages
- [ ] Home page works
- [ ] About page works and shows correct stats (150+, 500+, etc.)
- [ ] Services page works
- [ ] Blog page loads and shows posts
- [ ] Individual blog posts load with `/blog/:id` route
- [ ] Contact page works
- [ ] Portfolio/Videos section displays with thumbnails
- [ ] Footer displays correctly with updated colors

### Admin Dashboard
- [ ] Login page accessible at `/admin`
- [ ] Admin login works with correct credentials
- [ ] Dashboard overview loads stats
- [ ] 🌐 Web Content editor tab accessible
- [ ] 📹 Videos & Shorts tab accessible
- [ ] Can fetch YouTube metadata
- [ ] Can add new video items
- [ ] Blog management functional
- [ ] Site settings accessible
- [ ] Contact requests visible

### Contact Form
- [ ] Contact page form accepts input
- [ ] Form submits correctly
- [ ] Data appears in Google Form responses
- [ ] Submission shows success message
- [ ] Form submission is tracked in contact requests

### API Connectivity
- [ ] Backend API responds to requests
- [ ] CORS headers allow frontend requests
- [ ] Authentication tokens work
- [ ] Database queries return data
- [ ] File uploads (images) work if Firebase enabled

### Performance
- [ ] Homepage loads in < 3 seconds
- [ ] First Paint < 1 second
- [ ] No console JavaScript errors
- [ ] No CSS styling issues
- [ ] Mobile responsive (check at 375px, 768px, 1024px)

### Mobile Testing
- [ ] Responsive on iPhone (375px)
- [ ] Responsive on iPad (768px)
- [ ] Touch interactions work
- [ ] Forms accessible on mobile
- [ ] Videos play on mobile

### SEO & Metadata
- [ ] Meta tags present (title, description)
- [ ] Open Graph tags for sharing
- [ ] Favicon loads
- [ ] Robots.txt accessible
- [ ] Sitemap.xml accessible

## Monitoring (Post-Deploy)

- [ ] Set up Vercel analytics dashboard
- [ ] Monitor error logs for first 24 hours
- [ ] Check email for deployment notifications
- [ ] Monitor MongoDB connection errors
- [ ] Check Cloudinary upload status

## Rollback Plan (If Issues)

If critical issues after deployment:
1. [ ] Identify the issue (check Vercel logs)
2. [ ] Revert to previous working deployment
   - Go to Vercel Deployments
   - Find last successful deployment
   - Click "Redeploy"
3. [ ] Investigate issue locally
4. [ ] Fix and test thoroughly
5. [ ] Re-deploy when ready
